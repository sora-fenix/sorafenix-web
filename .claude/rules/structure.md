# Rule: directory structure

Read before creating a file, moving a file, or deciding where something belongs.

## Layout

Application code lives under `src/`. The repository root holds config only.

```
src/
  app/
    (marketing)/               # landing, pricing            -> /  /pricing
    (auth)/
      login/                   # magic-link form + server action
      auth/callback/           # PKCE code exchange
      auth/error/
    app/                       # authed product
      page.tsx                 # -> redirects to first workspace
      [workspace]/             # -> /app/{slug}/...
        dashboard/ leads/ companies/ contacts/
        campaigns/ inbox/ approvals/ knowledge/ settings/
        layout.tsx loading.tsx error.tsx not-found.tsx
    api/
      health/                  # liveness check
      webhooks/n8n/leads/      # lead ingestion (HMAC signed)
      webhooks/gmail/          # push notifications
      webhooks/whatsapp/       # inbound + status callbacks
      cron/                    # queue tick, sequence tick
  middleware.ts                # session refresh + /app guard
  instrumentation.ts           # boot-time env validation
  components/
    ui/                        # shadcn, generated — vendor code, do not hand-edit
    layout/                    # sidebar, topbar, workspace switcher, page shell
    crm/                       # domain-specific presentational pieces
  hooks/                       # client-only React hooks
  lib/
    env.ts                     # the ONLY file that reads process.env
    types/     result.ts
    db/        drizzle.ts browser.ts server.ts admin.ts middleware.ts
               schema/ queries/
    auth/      session.ts permissions.ts members.ts
    workspace/ slug.ts provision.ts
    ai/        agent.ts models.ts prompts/ schemas/
    leads/     dedupe.ts enrich.ts
    scoring/   rubric.ts score.ts
    outreach/  send-guard.ts email.ts whatsapp.ts
    sequences/ state-machine.ts runner.ts
    crm/       status.ts activity.ts

drizzle/                       # migrations (0001_rls.sql is hand-written)
scripts/       seed.ts seed-data.ts
docs/          SPEC.md PROGRESS.md ADR/
tests/         unit/ integration/ e2e/
.claude/       rules/ agents/ commands/ settings.json
```

## Rules

- **Routing.** Authed URLs carry a literal `/app` prefix (`/app/{workspace}/dashboard`),
  so the middleware matcher is exactly `['/app/:path*']` and a workspace slug can
  never collide with a marketing route.
- **Imports.** Always the `@/` alias, which maps to `src/`. No `../..` climbing
  between top-level directories. `scripts/` is the one exception: `tsx` runs it
  outside the Next runtime, so it reaches into `../src/…` relatively.
- **`src/components/ui/**` is vendor code** generated by the shadcn CLI. Regenerate
  it, do not hand-edit it. It is excluded from the eslint type-discipline block.
- **Business logic belongs in `src/lib/`,** not in a route handler or a page. A
  page composes; it does not decide.
- **Schema imports go through the barrel** `@/lib/db/schema`, never a domain file
  directly. Dependency order is strict and acyclic:
  `workspace ← crm ← outreach`, and `workspace ← ai`. A file may only import from
  files to its left. Needing the other direction means the table is in the wrong file.
- **Tests stay at the root** in `tests/`, mirroring the module they cover.
